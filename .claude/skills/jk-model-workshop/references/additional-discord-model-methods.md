# Additional Discord model-method findings from the downloaded corpus

Research synthesis, 30 September 2026. This pass searched the read-only 28,948-message index across all indexed channels with twenty FTS queries; 208 unique ranked hits were returned and six nearby-message windows were retrieved. Selected hits and relevant surrounding messages were inspected. Twenty-seven selected messages were matched back to their exact lines in the original saved capture and its full SHA-256 was verified. This is a bounded research pass, not a claim to have read or understood every message. The selected actionable additions happen to be from `editing`; the search was not restricted to it.

The [source ledger](evidence/additional-discord-model-methods.json) records precise message IDs, stable links, source hashes and attribution confidence. Quoted replies were separated from each author’s own message. No network requests, attachment downloads or game tests occurred. These are attributed historical reports and research recommendations, not newly reproduced fixes. The cases add concrete diagnostics, alternatives or compatibility boundaries to the earlier community-method guides.

1. **Check the indexed-MAT import path before changing a texture to cure a Blender transparency artifact.** Urgon diagnosed garbage alpha metadata in some stock MAT color-format structures: a test for `alpha.bpp > 0` was causing the importer to connect texture alpha to the BSDF. He proposed an indexed-color-mode guard; Stormtrooper reimported the same `ky.3do` and reported a normal rendered viewport with the erroneous connections absent. This is a useful regression fixture: retain the original MAT, inspect shader connections, and compare the same import before/after the importer change. It does not establish that the current fork still has this bug, nor that every indexed MAT is affected. Credit Urgon for the diagnosis and Stormtrooper for the paired retest. Sources: [diagnosis](https://discord.com/channels/881034839401328680/881044857328652328/1470858245873860769), [guard proposal](https://discord.com/channels/881034839401328680/881044857328652328/1470858308146561237), [retest](https://discord.com/channels/881034839401328680/881044857328652328/1470861372387753995), 10 February 2026.

2. **A bake with no animation is a useful control for rig/rest-pose debugging.** Stormtrooper removed the animation armature and still reproduced separated forearms/hands. A save from before adding constraints stayed intact, whereas removing constraints from a later save did not restore it. Later messages implicated upper-arm base rotation and a rotation applied between armature creation and constraint assignment. The geometry became intact, but he explicitly reported that arm rotation remained wrong. Recommended experiment: compare pre-constraint, post-constraint and zero-motion bake checkpoints; record rest transforms before applying them. Do not promote the partially successful rotation change into a guaranteed baking recipe. Shred's constraint investigation helped direct this work; Stormtrooper supplied the controlled comparisons and limitations. Sources: [control](https://discord.com/channels/881034839401328680/881044857328652328/1293785355371155558), [base pose](https://discord.com/channels/881034839401328680/881044857328652328/1293796775093604434), [transform history](https://discord.com/channels/881034839401328680/881044857328652328/1293797397062877205), [partial result](https://discord.com/channels/881034839401328680/881044857328652328/1293823449114087495), 10 October 2024.

3. **Isolate scene state when KEY export says an existing node is missing.** Shred reported that an imported Kyle could not export a KEY because `k_torso` was not found; creating a fresh scene and appending the model made it work. Stormtrooper independently reported using the same workaround, without diagnosing the cause. A fresh-scene copy is therefore a reversible diagnostic option before renaming or rebuilding an otherwise intact hierarchy. Save the failing scene for a proper importer/exporter regression case. This is an observed historical workaround, not proof of a current reproducible addon bug. Sources: [Shred's failure](https://discord.com/channels/881034839401328680/881044857328652328/1293728010683416628), [workaround](https://discord.com/channels/881034839401328680/881044857328652328/1293728992477577349), [Stormtrooper corroboration](https://discord.com/channels/881034839401328680/881044857328652328/1293729994945728532), 9 October 2024.

4. **Distinguish an animation editor's binding assumptions from a bad native animation.** shimstock reported octopus KEYs working in game but failing in PJedi. Stormtrooper found matching numeric node designations with different names, suspected index binding in the engine versus name binding in PJedi, and reported correct playback in Blender-Sith. He suggested removing a leading character from the octopus hierarchy names except `$$$DUMMY` for PJedi. The safe option is an editor-only copy with a recorded name mapping; preserve the original native asset until index/name semantics have been checked in the target engine. This is a particularly useful creature-rig counterexample to assuming that one editor's failure proves invalid KEY data. The engine explanation remains the participant's hypothesis here. Sources: [shimstock's report](https://discord.com/channels/881034839401328680/881044857328652328/1477155244549865502), [binding hypothesis](https://discord.com/channels/881034839401328680/881044857328652328/1477161955562356808), [Blender-Sith comparison](https://discord.com/channels/881034839401328680/881044857328652328/1477163035989770296), [PJedi workaround](https://discord.com/channels/881034839401328680/881044857328652328/1477166900898435072), 27–28 February 2026.

5. **For a second weapon attachment, distinguish the PUP role number from its mapped 3DO node.** Stormtrooper's Kyle example maps both primary and secondary fire roles to node 12 (`k_rhand`). His dual-saber advice is to add a suitable new model node and point the secondary-fire role at it, rather than merely assuming the secondary role already denotes a separate hand. This makes an explicit diagnostic table useful: PUP role → numeric hierarchy node → intended attachment. Native stock-file corroboration and animation-allocation checks remain necessary before adopting this in a release. Sources: [dual-saber advice](https://discord.com/channels/881034839401328680/881044857328652328/1294079041841664046), [role/node example](https://discord.com/channels/881034839401328680/881044857328652328/1299590566337843252), 10 and 26 October 2024.

6. **Test attachment origins when evaluating pivot cleanup.** Shred explained that removing the relevant offset can put a saber blade at the wrist instead of the end of the saber, and observed offsets elsewhere in the Kell Dragon. A body that looks unchanged in a pose viewer is therefore insufficient evidence that its offsets are redundant. Add an activated-saber/weapon-origin comparison to a zero-pivot experiment and keep an untouched original. His speculative remark about what offsets are useful for must not be generalized into a complete definition of native pivot semantics. Source: [Shred](https://discord.com/channels/881034839401328680/881044857328652328/1305392288255709184), 10 November 2024.

7. **A hovering replacement actor with a much larger interaction envelope may be a template-size problem.** KnightCop's AT-ST-derived replacement rose back into the air after walking and blocked the player far outside the visible legs. SMLiberator recommended matching the original AT-ST's `size` and `movesize`; KnightCop reported that this resolved the problem. The combined symptom is more diagnostic than hovering alone. Compare the new and old template values and collision envelope before repeatedly shifting the mesh or insertion offset. Copying old dimensions is appropriate only when the replacement should keep the same collision behavior. Sources: [symptoms](https://discord.com/channels/881034839401328680/881044857328652328/1216325337537970277), [diagnosis](https://discord.com/channels/881034839401328680/881044857328652328/1216327445041385492), [reported result](https://discord.com/channels/881034839401328680/881044857328652328/1216335966713679973), 10 March 2024.

8. **Using MP bodies as SP actors needs a spawn-count and weapon-state test matrix.** Stormtrooper described assigning weapon mesh and armed mode from the actor COG's creation path. He reported success in OpenJKDF2 but missing weapon meshes in vanilla JK after roughly sixteen actors and for dynamically spawned actors. He also called for throw/punch event markers, corresponding PUP major modes, and a fist-mesh replacement when Force Pull removes a weapon. A later MotS example was described by its author as only lightly tested. Practical additions to validation are preplaced versus dynamically created actors, increasing concurrent counts, throw/punch timing, and armed → disarmed transitions. The approximate sixteen figure is not a measured universal engine limit. The JK report and lightly tested MotS attachment must remain separate compatibility claims. Sources: [method](https://discord.com/channels/881034839401328680/881044857328652328/1292895126850637955), [retail caveat](https://discord.com/channels/881034839401328680/881044857328652328/1292895775780634644), [KEY/PUP requirements](https://discord.com/channels/881034839401328680/881044857328652328/1292896347925778614), [Force Pull](https://discord.com/channels/881034839401328680/881044857328652328/1292896802168635424), [MotS qualification](https://discord.com/channels/881034839401328680/881044857328652328/1293036909685248031), 7 October 2024. The attachment binary was not inspected in this pass.

9. **Correspondence-based native KEY editing is an alternative to a full modern rig pipeline.** shimstock reported adapting Ree-Yees thermal-detonator throw and punch animations to a stormtrooper by copying PYR values between corresponding meshes. The resulting NPC was explicitly unfinished: locomotion still looked like it held a gun while empty-handed. This gives users a bounded option for close rigid rigs: document a node correspondence and transform interpretation, transfer a small action, then validate the entire idle/walk/attack state set. Do not infer that arbitrary unlike skeletons can share rotations unchanged. Source: [shimstock's proof of concept](https://discord.com/channels/881034839401328680/881044857328652328/1293734803824443432), 9 October 2024. The attached ZIP was not inspected.

10. **Native animation can also be an input to a modern animation workflow.** Stormtrooper reported importing an original saber-draw KEY, baking it onto an armature, exporting FBX and successfully reimporting that FBX into Blender. This suggests an alternative to generating replacement motion from scratch: use known native motion as the reference and test a round trip before substantial editing. Preserve timing, node mapping and attachment behavior as separate checks. The report establishes the author's claimed Blender round trip, not equality of every frame or successful export of the resulting animation back into retail. Source: [Stormtrooper](https://discord.com/channels/881034839401328680/881044857328652328/1473225902954647602), 17 February 2026.

## Attribution and exclusions

Credit Shred for the scene-isolation workaround and the attachment-offset distinction, Urgon for the indexed-MAT importer diagnosis, Stormtrooper for the many carefully bounded animation/import/actor reports and follow-up tests, SMLiberator for the actor-template diagnostic, KnightCop for the useful symptom report and retest, and shimstock for the creature-editor counterexample and native KEY-transfer experiment. These contributions are distinct and must not be collapsed into a generic claim that one person invented the whole workflow.

Quoted reply text preceding an own-message header was not attributed to the replying author. The MAT diagnosis, AT-ST discussion and MP-actor reply contain such boundaries in the saved capture. Attachment thumbnails and files were not treated as inspected evidence. Search hits involving unrelated shader systems, level-surface painting and already-covered generic mesh-budget advice were not promoted into new modeling findings. The current corpus is heavily weighted toward `editing` (27,744 documents under that label plus 210 under `editing, Text Channels`); this limits any claim about broader server coverage.
